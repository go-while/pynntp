The `SSLMode(ssl_mode)` coercion fixes a real bug: before, `use_ssl=True, ssl_mode="STARTTLS"` (or any other value that is not an SSLMode) matched neither branch in `_connect()`, so the client connected in plain text on port 119 and sent the login in clear text. That part is good to go. The trouble is the two new refusals. The `from_url()` one protects nothing and breaks the usage pattern `from_url()` exists for. The constructor one breaks existing callers, the repo's own integration tests among them.
